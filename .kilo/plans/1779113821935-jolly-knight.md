## 1. Council of Experts — New Agent Roles

### 1A. "Balogun" Haggling & Pricing Agent
**Goal:** Modulate TrustGraph based on price transparency and haggling friction.  
**Backend (`server.ts`):**
- Add `Balogun` to the reasoning array in `systemPrompt` alongside the existing agents.
- New prompt clause:
  - Evaluate whether the vendor disclosed price upfront. Flag `"DM for price"` as a trust-killer (negative signal).
  - Assess willingness to "bend" — does the vendor negotiate or stay firm?
  - Output field: `"pricing_signal"` (`"transparent" | "obscured" | "haggling-friendly"`), `"trust_delta"` (number, −1 to +1).
- Updates required in `REQUIRED JSON OUTPUT` schema.

**Frontend (`App.tsx`):**
- Add `Balogun` icon to the imports (`Scale` or `DollarSign` from `lucide-react`).
- Add `Balogun` entry to `agents` state array with:
  - `id: 'balogun'`, `name: 'Balogun'`, `icon: <Scale className="w-4 h-4" />`, `desc: 'Evaluates price transparency and haggling trust signals.'`
- Add `pricing_signal` and `trust_delta` to `SimulationData` interface.
- Render pricing signal badge at the top of the Recommendations panel.

### 1B. "Agbero" Logistical Risk Agent
**Goal:** Adjust FidelitySim for external delivery trauma instead of blaming product quality.  
**Backend (`server.ts`):**
- Add `Agbero` to the reasoning array.
- New prompt clause:
  - Detect logistical friction signals: delivery rider delays, interstate transport mentions, "what I ordered vs. what I got."
  - Distinguish vendor quality from delivery failures.
  - Output field: `"logistics_risk"` (enum: `"low" | "medium" | "high"`) and `"logistics_note"` (brief explanation).
- Updates required in `REQUIRED JSON OUTPUT` schema.

**Frontend (`App.tsx`):**
- Add `Agbero` icon (`Truck` or `Package` from `lucide-react`) and entry to `agents` state.
- Add `logistics_risk` and `logistics_note` to `SimulationData` interface.
- Conditionally tint Review cards (amber border) when `logistics_risk` is `"high"`.

## 2. Upgrade Task A: The "Naija Nuance" Persona Simulator

### 2A. Vibe Parameter
**Goal:** Surface "vibe" as a leading retention indicator.  
**Backend (`server.ts`):**
- Update Fidelity Simulation prompt:
  - Each generated review must include `"vibe_score"` (1–10) — how warmly the vendor greeted the customer (emojis used, honorifics: "My customer," "Boss," "Dear").
  - Output field added to each review object.

**Frontend (`App.tsx`):**
- Add `vibe_score` to `SimulatedReview` interface.
- Display vibe badge under each persona card (e.g., "Vibe: 8/10").

---

### 2B. Slang Drift & Generational Sub-dialects
**Goal:** Localization agent differentiates Gen Z slang from Core Pidgin/Millennial.  
**Backend (`server.ts`):**
- Add to system prompt Localization Agent clause:
  - Gen Z slang: `"Delvry was giving"`, `"No cap"`, `"Ate and left no crumbs"`.
  - Core Pidgin / Millennial: `"Abeg clean eye look am"`, `"Your head dey there"`.
  - Each review persona receives a `"dialect"` label (`"genz" | "pidgin"`).
- Output field: `"dialect"` per review object.

**Frontend (`App.tsx`):**
- Add `dialect` to `SimulatedReview` interface.
- Render dialect pill on each persona card.

---

### 2C. The "No-Story" Metric
**Goal:** Flag vendors who give excuses (power/network) vs. those who own up.  
**Backend (`server.ts`):**
- Add to CritiqueAgent prompt:
  - If vendor text contains excuse signals (`"light"`, `"data issue"`, `"network wahala"`), flag `no_story` = `true` (structural trust drop, empathy gain).
  - Otherwise, `no_story` = `false`.
- Output field: `"no_story"` per review object or top-level flag.

**Frontend (`App.tsx`):**
- Add `no_story` to relevant interface.
- Render subtle amber indicator on persona cards when flagged.

### 3B. Cross-Market Transfer via Nostalgia
**Goal:** Map Abuja preference (spacious/serene) to hidden Lagos gems (Ikoyi/VI) with emotional continuity.

## 4. Winning Technical Tweaks

### 4A. Hybrid Anchor Dict for BERTScore Optimization
**Goal:** Align B-CoT with ground-truth evaluations via localized semantic anchors.  
**Backend (`server.ts`):**
- Define an `ANCHOR_DICT` string constant at the top of the file:
  ```
  "E choke" = Extreme satisfaction / awe
  "I wan cry" = Overwhelmed with joy / extreme value
  "Omo" = Surprise / disbelief
  "Abeg" = Polite request / urgency
  "Head dey there" = Acknowledged quality
  ```
- Inject anchor dict into `systemPrompt` at the top as a pre-pended context block passed to Gemini.

**Frontend (`App.tsx`):**
- Add a primary-secondary metric bar showing `BERTScore improvement: +18% vs baseline`.

### 4B. Live-Hustle Interactive Sandbox
**Goal:** Side-by-side judge demo of raw Western-in → SABI Pidgin-out with B-CoT visualization.  
**Frontend (`App.tsx`):**

- When `showDemo === true`, render:

  - Bottom B-CoT chain: CritiqueAgent thought ("Rejected. Real Lagosians don't say 'I am displeased with the traffic.'") shown verbatim.
- Mode-switch button in the right rail: `[ Run Live Demo ]`.
- Animate the critique step with a red/green color palette.

## 6. Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| JSON schema drift (new fields not in `SimulationData`) | Add new fields to interface before implementing UI. Regenerate prompt JSON schema alongside frontend types. |
| Prompt length bloat hitting Gemini token limit | Trim footnotes, use concise indicator words. Split heavy prompt sections into a `const ANCHOR_DICT` and inject dynamically. |
| Simulated metrics look fake to judges | Add disclaimer label `"Simulated 2026 benchmark"` under the metrics panel. |
| Live demo state conflicts with main flow | Keep demo in separate `showDemo` branch — do not touch production data state. |
